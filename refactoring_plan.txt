  BeepBeep 야구 훈련 앱 — 전체 리팩토링 분석 보고서
  작성일: 2026-05-28
================================================================================

[ 프로젝트 개요 ]
- 시각장애인 야구 훈련용 Android 앱
- 헤드트래킹: 스마트폰 내장 IMU 센서 (GAME_ROTATION_VECTOR)
- 타격 훈련: 직접 제작한 BLE 배트 (SmartBat_Pro, 버튼 2개 내장)
- 수비 훈련: 외부 게임 컨트롤러 (EasySMX X05 Pro)
- 오디오:   Resonance Audio (3D HRTF, ITD, 도플러 적용)
- 백엔드:   Firebase Firestore

[ 읽는 방법 ]
- "테스트 코드" = 배트 하드웨어 완성 전 임시로 폰 센서를 배트처럼 쓰던 코드. 제거 대상.
- "중복 코드"   = 2개 이상 파일에 동일 로직이 복붙되어 있는 부분. 공통 클래스로 통합 가능.
- "분리 가능"   = 한 파일이 너무 커서 역할별로 나눌 수 있는 부분.
- "삭제 가능"   = 미사용 필드/라이브러리 등 완전히 제거해도 되는 것.

[ 수비 훈련 버튼 구조 확인 결과 ]
  수비 훈련(MainActivity)은 이미 올바른 구조.
  - 비관리자: 화면 버튼 없음, 컨트롤러(A/B/X/LB/RB + 아날로그 스틱)로만 동작
  - 관리자:   화면 버튼 + 컨트롤러 병행 (개발/테스트 목적, 의도된 동작)
  - 수비 훈련에서 제거할 테스트 코드 없음

[ BaseRunReactionActivity 처리 방침 ]
  - 현재 앱 내 어디에서도 진입 불가능한 화면 (Intent 호출 코드 없음)
  - 이번 리팩토링에서 건드리지 않고 현 상태 유지
  - 전체 리팩토링 완료 + 앱 테스트 통과 후 파일 삭제

[ PendingUploadManager 위치 ]
  - 팀원이 추가한 오프라인 저장/자동 동기화 파일
  - SwingTestActivity → SwingDataRecorder 로 분리 시 해당 파일에 포함
  - MainActivity → networkCallback 과 함께 유지
  - 파일 자체는 분리/수정 없이 그대로 사용
